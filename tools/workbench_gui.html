Live observations from the Diagnostic Switch, unauthenticated and unencrypted by default. This receiver cannot change gameplay, send controller commands or activate the Switch stream.

1 · Connect the receiver

The local receiver starts automatically. In its dashboard, enter the Switch private IPv4 and telemetry port (4243). No config file or manual key is needed.

2 · Activate in Training

On Diagnostic: Fighter Settings → Developer tools → Live telemetry UDP. Activate explicitly each session. Training LAN editing is a separate service.

3 · Inspect fresh samples

Choose an observed object, data group and field. Stale means no fresh sample for 250 ms, not a game pause or measured network latency.

Receiver setup & troubleshooting

The receiver starts automatically with the GUI, without reading local or SD pairing files. It uses the existing Rust host example and offline Cargo cache; first startup may compile. No dependencies are downloaded. Allow UDP replies on this computer on your trusted private LAN; do not forward router ports. Enter the Switch address in the dashboard and activate telemetry explicitly in Diagnostic Training. Default packets are not authenticated or encrypted. Closing Workbench stops its receiver.

Set the version, confirm the Switches are ready, then build and upload in one click.

1 version → 2 Switches → 3 ready check → 4 Build + Upload

Diagnostic only uploads release files, preserves Diagnostic’s current active/staged sequences and does not contact Silent. Both/Silent uploads download Silent’s active sequences.txt, restores matching repository comments, updates the split fighter files and assembled deployment file, then replaces active files on selected Switches with verified backups. Smash must be closed on the Silent Switch too so its saved sequence data is not overwritten during synchronization. Build actions write the version above into Cargo.toml first.

Edit one fighter

Read a file once, change a single fighter's sections, review the diff, then save. Other fighters and universal settings are preserved.



Deleting all text removes the fighter from the file. Saving validates with the current parser, keeps a recovery backup and verifies the written bytes. A Switch destination also needs Smash closed and the ready checkbox on Ship a version.


Training LAN editor + live logs


Activate the Diagnostic server explicitly in Training on the Switch. Reads require Training; saving requires its editor open. This is separate from FTP and never controls the Silent build.






No manual key is needed. UDP is preferred; HTTP remains available on the same diagnostic port. No transport fallback, DNS, proxy, redirects, discovery or automatic reconnect. Reads time out after two seconds; save acknowledgment after ten seconds. Any transport/protocol error disconnects; a lost save acknowledgment does not mean disk is unchanged. Reconnect and load again manually, never retry a save automatically. Only address/port are saved locally.
